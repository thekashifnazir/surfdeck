# Requirements: Cycle 6 — "Telly Is the Destination"

## Introduction

The surfed site plays INSIDE the telly screen via an iframe. The remote collapses to its essentials (SURF + moods + INPUT); all secondary filters move into a single flyout disclosure. The provenance card persists beside the telly so it can be read while viewing the embedded site.

The Remote + Card Printer metaphor, palette, fonts, and ceremony rules are untouched. Full ceremony fires on first press only; the tuned channel persists between presses. This spec also bundles three verified bug fixes from code review.

---

## Glossary

- **Embedded channel:** A surfed site displayed inside the telly screen in a sandboxed iframe.
- **Embeddable flag:** A precomputed boolean indicating whether a site's HTTP headers permit framing.
- **TUNE flyout:** A single disclosure panel on the remote that surfaces all secondary filters (character, stack, host, static/dynamic, corner tiers).
- **Pop-out button:** A bezel control on the telly that opens the current embedded site in a new tab.
- **Non-embeddable fallback:** The existing new-tab behaviour, triggered when `embeddable = false`.

---

## Requirement 1: Embedded Channel — iframe in the Telly

**User Story:** As a visitor, I want the surfed site to play inside the telly screen so I can browse without leaving Surfdeck.

### Acceptance Criteria

1. WHEN `embeddable = true` for the surfed site, the telly screen SHALL render a sandboxed `<iframe>` filling 100% of the screen area.
2. THE telly container SHALL grow to approximately 70% of the desktop layout width when an iframe is loaded (the remote stays at 240px fixed).
3. THE iframe `sandbox` attribute SHALL include: `allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox`.
4. THE iframe `sandbox` attribute SHALL NOT include `allow-top-navigation` or any variant (`allow-top-navigation-by-user-activation`, `allow-top-navigation-to-custom-protocols`).
5. THE iframe SHALL have `referrerpolicy="no-referrer"`.
6. THE iframe SHALL have no `allow` attribute (no Permissions-Policy delegation).
7. DURING the zap ceremony the iframe SHALL NOT be visible — the snow/static and tuned overlay play as normal; the iframe fades in only after the ceremony completes.
8. THE existing zap state machine (idle → zapping → tuned) SHALL NOT change in structure.

---

## Requirement 2: Pop-Out Button on the Telly Bezel

**User Story:** As a visitor viewing an embedded site, I want a button on the TV bezel to open the current site in a full new tab whenever I choose.

### Acceptance Criteria

1. A pop-out button SHALL appear on the telly bezel (outside the screen, inside the TV body padding) when a site is embedded.
2. THE button SHALL open the currently-embedded URL in a new tab via `window.open(url, '_blank')`.
3. THE button SHALL have a recognisable "external link" icon (SVG, no icon library).
4. THE button SHALL meet the 44px minimum touch target.
5. THE button SHALL be hidden when no site is loaded (idle state) or when the site opened in a new tab (non-embeddable fallback).

---

## Requirement 3: Embeddable Flag — Precomputed Pipeline

**User Story:** As a developer, I want a precomputed embeddable flag so the client never has to guess whether a frame will load.

### Acceptance Criteria

1. A NEW pipeline script (`scripts/check-embeddable.ts`) SHALL HTTP-HEAD each corpus URL and inspect `X-Frame-Options` and `Content-Security-Policy: frame-ancestors` headers.
2. THE result SHALL be stored as an `embeddable` column in the D1 `sites` table (INTEGER NOT NULL DEFAULT 1: 1 = embeddable, 0 = not embeddable).
3. A D1 migration (`schema.sql` addendum or standalone migration script) SHALL add the column.
4. THE seed script SHALL populate the `embeddable` column at seed time from precomputed results (a JSON lookup file generated by the pipeline script).
5. THE CSV column count SHALL NOT change — the embeddable flag is D1-only, not a CSV column. The 12-column validator contract in `scripts/lib/validate-csv.ts` remains untouched.
6. THE `/api/surf` response SHALL include `embeddable: boolean` alongside the existing site fields.
7. THE pipeline script SHALL treat network errors or timeouts as `embeddable = true` (optimistic — worst case is a blank frame the user can pop out).
8. THE pipeline script SHALL cache results in `.embeddable-cache/` (gitignored) so re-runs only check new/changed URLs.

---

## Requirement 4: Non-Embeddable Fallback

**User Story:** As a visitor, I want a clear in-metaphor message when a site won't load in the telly, and the site still opens in a new tab so I never lose the catch.

### Acceptance Criteria

1. WHEN `embeddable = false`, the site SHALL open in a new tab exactly as the current behaviour (window.open on surf press).
2. THE telly screen SHALL show a fallback state: warm off-white background (#F2F0E9) with text: "this channel won't tune in — opened across the room" in Doto 12px, ink colour, centered.
3. THE provenance card SHALL still print normally for non-embeddable sites.
4. THE LCD SHALL still show `TUNING > CH {n}` during the ceremony and the channel persists after.
5. THE pop-out button SHALL be hidden during the fallback state (the tab is already open).

---

## Requirement 5: Filter Consolidation — TUNE Flyout

**User Story:** As a visitor, I want the remote to feel clean at rest — only SURF, moods, and INPUT visible — with advanced filters available in one disclosure.

### Acceptance Criteria

1. AT REST the remote SHALL show only: IR LED, LCD, SURF key, mood keys (3×2 grid), INPUT key — nothing else visible.
2. A "TUNE" key SHALL appear below the INPUT key, styled as a chiclet matching INPUT (full-width, same shadow/radius rules).
3. PRESSING "TUNE" SHALL toggle a flyout panel that overlays or expands below the remote (design decision for design.md).
4. THE flyout contents SHALL depend on the active INPUT mode:
   - **OPEN WEB mode:** character filter chips, stack chips, host chips, static/dynamic chips.
   - **VIBECODED mode:** corner tier chips.
5. THE flyout SHALL include a "CLEAR ALL" action that resets all secondary filters to their defaults.
6. THE LCD readout SHALL summarise active filters, e.g. `CH 218 · BEAUTY · NEOCITIES`. Format: channel (if tuned) + mood (if selected) + one active secondary filter label (if any). If multiple secondaries, show count: `+ 2 MORE`.
7. THE existing `<section className="filters">` below the scene SHALL be removed — all filter UI lives on the remote.
8. CHARACTER, stack, host, static/dynamic, and corner tier filter CHIPS SHALL retain their current 44px min-height touch target.

---

## Requirement 6: Provenance Card — Beside the Telly + Content Upgrade

**User Story:** As a visitor, I want to read the provenance card while looking at the embedded site, and I want to see the site title and curator note alongside provenance data.

### Acceptance Criteria

1. THE provenance card SHALL render in a column to the right of the telly (desktop), or below the telly (mobile ≤768px).
2. THE card SHALL persist between presses (unchanged behaviour).
3. THE card heading SHALL now include the site title: `"{title}" — CATCH № {siteId} OF {TOTAL}`.
4. THE card body SHALL gain the curator's `why_note` as a line below the provenance fields, styled italic in body-grey.
5. THE existing provenance fields (stack · host · static_or_dynamic), fallback text, and footer SHALL remain unchanged.
6. THE `CORPUS_TOTAL` constant SHALL be fetched from a new `/api/corpus-size` endpoint (returns `{ total: number }`) instead of hardcoded — future corpus growth is automatic.
7. THE card "OPENS IN NEW TAB" stamp SHALL change to "OPENS IN TELLY" when the site is embedded, and remain "OPENS IN NEW TAB" for non-embeddable fallback.
8. THE card print animation (firstprint/reprint) SHALL remain unchanged.

## Requirement 7: Bug Fix — Press-Note Layout

**User Story:** As a visitor, I don't want the press-note to steal telly width by acting as a third flex column.

### Acceptance Criteria

1. THE `<p className="press-note">` element SHALL be moved OUTSIDE the `.scene` flex row.
2. IT SHALL render below the telly-container (after the card slot, before the status message).
3. THE `.scene` flex row SHALL have exactly two children: the remote and the telly-container (plus provenance card column on desktop).
4. THE press-note text content and evolving logic (0/1/2+ presses) SHALL remain unchanged.
5. THE press-note SHALL be centred and styled: italic, caption-grey #8A867A, 12px, Familjen Grotesk.

---

## Requirement 8: Bug Fix — First-Press Card Delay

**User Story:** As a visitor on my first press, I want the card to print with a visible delay after the static clears — not instantly.

### Acceptance Criteria

1. THE first-press card delay SHALL be a POSITIVE value that produces a visible pause between the tuned-overlay appearing and the card beginning to print.
2. THE computation `cardDelay - staticDuration` (currently 600 - 800 = -200ms) SHALL be fixed so first-press uses a net positive delay (suggested: `cardDelay = 1200`, producing 1200 - 800 = 400ms net delay).
3. COMPRESSED presses SHALL retain their current ~100ms net delay (500 - 400 = 100ms — already correct).
4. THE fix SHALL NOT change any animation duration constants in CSS — only the JS timer scheduling in App.tsx.

---

## Requirement 9: Bug Fix — LCD Channel Number After Mood Selection

**User Story:** As a visitor, I want to see my channel number on the LCD even when a mood is selected, once I've tuned in.

### Acceptance Criteria

1. WHEN tuned (zapState === "tuned") AND a mood is selected, the LCD SHALL show `CH {n} · {MOOD_LABEL}` — not just the mood label.
2. WHEN idle and a mood is selected (before any surf), the LCD MAY show just the mood label (current behaviour, acceptable since no channel has been assigned yet).
3. THE `TUNING > CH {n}` display during zapping SHALL remain unchanged.
4. THE no_match override (`NOTHING IN THAT CORNER RIGHT NOW`) SHALL still take precedence over all other LCD states.

---

## Requirement 10: Constraints

### Acceptance Criteria

1. NO new npm dependencies or frameworks SHALL be added. React/TS/CSS only.
2. `tsc --noEmit` SHALL produce zero errors.
3. ALL existing 115 tests SHALL pass without modification.
4. NEW behaviour (iframe, flyout, card upgrade, bug fixes) SHALL have new test coverage.
5. MOBILE layout at 390px SHALL have no horizontal scroll.
6. NO gold, dark-glow gradients, or handwriting fonts SHALL appear anywhere.
7. THE palette, font faces, and ceremony timing values from the design-direction steering file SHALL remain unchanged.
8. THE `window.open` call for non-embeddable sites SHALL remain the FIRST action in the surf handler (never gated on animation).
9. `prefers-reduced-motion: reduce` SHALL show end states statically for all new elements (iframe visible immediately, flyout open without transition, card at translateY(0)).
