**74 · The ouroboros that wasn't there — a routing bug the unit tests couldn't see, caught in a browser.** After task 5 shipped "green" — 3 passing route tests, `tsc` clean, and a header-less `curl http://localhost:5173/ouroboros` that returned the colophon — a glance at the same URL *in an actual browser* showed the normal surf app, not the colophon. The two disagreed, and the browser was right. Root cause: `wrangler.jsonc` pairs `"compatibility_date": "2025-04-01"` with `"assets": { "not_found_handling": "single-page-application" }`, and Cloudflare's docs are explicit — at that compatibility date or later, a **navigation request** (one carrying `Sec-Fetch-Mode: navigate`, which every browser attaches when you visit a URL) to a path with no matching static asset is served `index.html` by the Assets system *before the Worker ever runs*. So the Hono `/ouroboros` route — mounted correctly first in `index.ts` back at task 5.2 — was unreachable for real visitors; **Requirement 9.1 ("served by the Worker, not the SPA fallback") was not actually satisfied**, the mount-order fix being necessary but not sufficient. The reason it hid so well is the reason it was worth writing down: the single header that distinguishes "a browser navigating" from "a script fetching" is the exact header the feature keys on, so `curl` and the isolated route tests sailed straight past it. **Lesson banked: to verify a user-facing route, send the headers a user's browser sends** (`Sec-Fetch-Mode: navigate`) — reproducing with those headers turned the colophon into the SPA shell on demand, and the vite dev server was never lying, it was faithfully emulating production.

The fix is one line Kiro authored in `wrangler.jsonc`: `"run_worker_first": ["/ouroboros"]`, which forces that path to the Worker ahead of the SPA fallback (`run_worker_first` accepts an array of route patterns in wrangler 4.124.0). Nothing else changed — no Worker code, no route, no test — and `tsc` stayed clean with the suite at 87. Verified from outside rather than on the config's word: the identical browser-navigation request that had returned `<title>Surfdeck</title>` + `id="root"` now returns `<title>Surfdeck — The Ouroboros</title>` + "The loop closes.", with zero SPA markers. That request runs against the real workerd + Assets emulation the CF Vite plugin stands up, so the same emulation that reproduced the bug now reproduces the fix — as decisive as it gets short of the live edge, which stays on the deploy checklist (task 8) as the final confirmation. This behaviour can't be pinned by a vitest unit (the route handler was always correct in isolation; the defect lived in the platform's asset-vs-Worker precedence, which only the real runtime exercises), so the browser-header request against the emulated runtime *is* the regression check, recorded here in lieu of a unit test. The ouroboros page's visuals stay a bare placeholder by choice — the real glyph and "you found the maker" treatment are deliberately deferred to the Cycle 4 design pass; this entry is only about making the distinct page actually reachable.
